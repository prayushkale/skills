# Viral MV

## Overview
Don't ask a video model to invent the dance. Build a cheap **anime 3D driver** that dances exactly
on the beat, let a **reference-to-video model** re-skin it as a realistic character, then add all
text and graphics **in code, afterwards**. Choreography timing, cuts and lyrics stay deterministic;
only the pixels of the character are generated.

Pairs with the `viral-song` skill: write the song first, then use this for the video.

## Workflow
Do one stage at a time. After every generation stage, **STOP and ask the user numbered
questions**; there are no automated taste checks.

1. **Lock the audio.** Cut the song to the clip length. Have the user tap lyric timings against a
   slowed, zoomable waveform (ignore key repeats) into a `timeline.json`; AI word timestamps are
   only a first draft. Synthesize pops for unsung syllables. Save the beat offset (bars start at
   `offset + 2k s` at 120 BPM).
2. **Build the driver.** Use a three.js scene with a free VRM avatar (check its licence). Map lyric
   keywords to a move library, a groove, an emotion track and props; one camera cut per bar, a
   pulse on beat 3. The state is a pure function of time, so render frame by frame. Export a clean
   version: white background, character only, no text. This is the video model's driver.
3. **Make an original character image.** Use an image model (Seedream 5 Pro beat Nano Banana Pro
   here) and edit it for small changes. Generic traits only. Never a lookalike of a copyrighted
   character or a real person's photo.
4. **Bake off on 5 s.** Same driver slice, same image, 2–3 models. Show the user a labelled grid
   with the song. Pick the winner on what **they** rank highest (here: facial expression over
   identity accuracy). See `references/video-models.md`.
5. **Run the full clip once** on the winner. Quote the price first and wait for an explicit OK.
6. **Fix without regenerating.** Whiten a grey backdrop with a levels and luma/saturation key
   (`references/pitfalls.md`). Never re-roll a $15 pass for a cosmetic issue.
7. **Graphics layer.** Render the same studio in overlay mode (alpha, character hidden but its face
   position projected) and composite over the video. Follow `references/graphics-rules.md`.
8. **Composite and check at 2 fps** that nothing covers the face. Mux the song audio.
9. **User review, then post.**

## Paid calls
Quote the price (`get_pricing` plus the model page) and wait for an explicit OK. Log every request
ID, seed and cost in a `jobs.json`. Track spend against a stated cap. If a safety filter declines a
job, report why. Retry only with the user's OK and a **real content change**; never disguise it.

## Common mistakes
| Mistake | Fix |
|---|---|
| Many 3 s image-to-video clips stitched together | One driver-led pass; the dance and cuts come from the driver |
| Text or graphics generated by the video model | Composite in code afterwards |
| Asking for "plain white studio" and trusting it | It returns grey; make the driver background match, or whiten in post |
| Re-running to fix backdrop colour | Levels + key pass, no regeneration |
| Adding post-camera crops to a model that already copies the driver's cuts | Check the raw output first |
| Phone in the character's hands | Two-thumb gesture only |
| Claiming a lookalike was made | Offer generic traits instead |
| Promising virality | "Built from what hits share; post it and measure" |
